# Передай — обмен файлами по короткой ссылке

Готовое приложение на Go: PostgreSQL хранит метаданные, ваше S3-совместимое хранилище — файлы. Русскоязычный адаптивный интерфейс встроен в Go-бинарник через `go:embed`. Node.js и сборка фронтенда для запуска не нужны.

## Запуск

1. Нужны Go **1.26.2+**, PostgreSQL и существующий приватный S3-бакет.
2. Заполните `.env` по образцу [.env.example](.env.example). Если `.env` уже есть, сохраните свои значения. Приложение читает его автоматически; переменные окружения имеют приоритет.
3. Выполните:

   ```sh
   go run .
   ```

4. Откройте <http://localhost:8080>.

Таблицы создаются автоматически при старте. Обновление совместимо с двумя исходными goose-миграциями проекта; отдельно запускать goose не нужно. Версия схемы записывается в `filedrop_schema_migrations`, одновременные запуски защищены PostgreSQL advisory lock.

Основные настройки:

| Переменная | Назначение |
| --- | --- |
| `S3_ENDPOINT` | Домен S3 API без `https://` и без пути |
| `S3_ACCESS_KEY`, `S3_SECRET_KEY` | Ключи доступа к вашему хранилищу |
| `S3_BUCKET` | Имя существующего бакета; по умолчанию сохранён бакет из исходного `main.go` |
| `S3_SECURE` | HTTPS; по умолчанию `true`, `false` — для локального MinIO |
| `S3_REGION` | Необязательный регион провайдера |
| `DB_USER`, `DB_PASSWORD`, `DB_NAME` | PostgreSQL |
| `DB_HOST`, `DB_PORT` | По умолчанию `localhost`, `5432` |
| `DB_SSL_MODE` | По умолчанию `disable`; для удалённой БД задайте режим вашего провайдера |
| `HTTP_ADDR` | По умолчанию `:8080` |
| `UPLOAD_TEMP_DIR` | Каталог временных файлов; по умолчанию системный |

При старте проверяется доступ к бакету и БД. Ключам S3 нужны права чтения, записи, удаления объектов и проверки бакета. Бакет должен быть приватным: загрузка и скачивание проходят через Go, CORS для S3 настраивать не требуется. Для физического удаления по сроку используйте бакет без Object Lock и версионирования; при включённом версионировании провайдер может сохранять старые версии.

## Что работает

- Один файл за передачу: выбор на устройстве или drag-and-drop.
- Прогресс, отмена и понятные ошибки; при сбое завершающего запроса можно повторить создание ссылки без повторной загрузки.
- Короткая ссылка `/s/<12 символов>`: имя, фактический тип, размер, время загрузки и оставшийся срок.
- Скачивание с исходным именем, принудительным `attachment` и поддержкой HTTP Range.
- Лимит **2 147 483 648 байт (2 ГиБ)** включительно. Пустые файлы не принимаются.
- Файл доступен **12 часов от успешного сохранения в S3**. Повторное завершение загрузки не продлевает срок.
- После истечения срока API и скачивание немедленно возвращают `410 Gone`. Фоновый процесс запускается при старте и каждую минуту удаляет просроченные объекты; при недоступности S3 повторяет удаление. Уже начатое скачивание может завершиться после истечения срока.
- Незавершённые загрузки очищаются через час. После удаления остаётся запись в БД, чтобы отличать истёкшую ссылку от несуществующей; содержимое файла хранится только в S3.

## Проверка файлов

Сервер не доверяет имени, Content-Type и заявленному размеру. Он ограничивает объём входящего тела, сравнивает фактический размер, проверяет сигнатуру и только затем загружает объект в S3. Повторно записать файл по тому же адресу нельзя; публичная ссылка появляется только после завершения.

Запрещены `application/x-msdownload` и другие исполняемые типы, расширения EXE, DLL, MSI, BAT, CMD, PowerShell, VBS, JAR, ярлыки, установочные образы и shell-скрипты. По сигнатуре также отклоняются PE/DOS, ELF, Mach-O, Java class, shebang и OLE-контейнеры, включая старые DOC/XLS/PPT. Для документов используйте PDF или DOCX/XLSX/PPTX.

Поддерживаются **ZIP, TAR, GZIP и TAR.GZ без пароля**. Проверяются пути, вложенные файлы и их сигнатуры; запрещены символические ссылки и опасные файлы внутри архива. Лимит распакованных данных — 2 ГиБ суммарно, до 10 000 записей, максимум три уровня вложенных архивов. Вложенные контейнеры тоже учитываются в бюджете распаковки. DOCX/XLSX/PPTX проверяются как ZIP. Неподдерживаемые и зашифрованные архивы отклоняются.

Это фильтрация типов и содержимого архивов, **не антивирусная проверка**: она не гарантирует отсутствия вредоносного кода в PDF, документах или произвольных данных. Для такой гарантии нужен отдельный антивирусный сканер; сейчас он не подключён.

Перед сохранением файл временно записывается на диск, а не целиком в оперативную память. Одновременно обрабатываются две загрузки; для них и проверки вложенных архивов предусмотрите около **8 ГиБ свободного временного места**. Штатное завершение или отмена удаляет временные файлы; после аварийного выключения могут остаться файлы `filedrop-upload-*` и `filedrop-archive-*`.

## API

Все ошибки API — JSON вида `{"error":"..."}`. Поля запросов и ответов — `snake_case`.

| Метод | Адрес | Результат |
| --- | --- | --- |
| `POST` | `/api/uploads/init/` | Создать загрузку, получить `upload_id` и `upload_url` |
| `PUT` | `/api/uploads/{id}/content/` | Передать исходные байты файла, без multipart/form-data |
| `POST` | `/api/uploads/{id}/complete/` | Опубликовать ссылку и получить метаданные; идемпотентен |
| `GET` | `/api/share/{share_token}/` | Метаданные доступного файла |
| `GET` | `/api/share/{share_token}/download/` | Получить локальный `download_url` |
| `GET`, `HEAD` | `/download/{share_token}` | Скачать из приватного S3 после проверки срока |
| `GET` | `/healthz` | Проверить HTTP и подключение к БД |

Пример начала загрузки:

```json
{
  "original_name": "конспект.pdf",
  "size_bytes": 12345,
  "content_type": "application/pdf"
}
```

Ответ `201 Created`:

```json
{
  "upload_id": "<32 hex-символа>",
  "upload_url": "/api/uploads/<id>/content/"
}
```

`upload_id` — секрет управления загрузкой: его не нужно отправлять получателю. Для обмена используйте только `share_url` из ответа `complete`. Ссылка доступна любому, кто её знает. Срок хранения не является контролем доступа по личности.

Коды ошибок: `400` — некорректный запрос/архив, `404` — нет файла, `409` — неправильное состояние или повторная загрузка, `410` — срок истёк, `413` — превышен размер, `415` — запрещённый тип, `429` — частота запросов, `503` — заняты оба слота загрузки.

## Проверки и сборка

```sh
go test -race ./...
go vet ./...
node --check internal/web/static/app.js  # необязательно; проверка синтаксиса JS
go build -trimpath -o bin/filedrop .
```

Тесты покрывают HTTP-цикл, подмену содержимого и размера, архивы, повторные и конкурентные загрузки, срок хранения, Range и очистку. S3-адаптер проверяется через локальный HTTP-сервер с протоколом S3 и тестовыми ключами.

Для интеграционных тестов с настоящим PostgreSQL:

```sh
TEST_DATABASE_URL='postgres://user:password@localhost:5432/database?sslmode=disable' \
  go test -race ./internal/adapter/postgres -v
```

Тесты создают случайную изолированную схему и удаляют только её. Проверяются чистая база, исходные goose-миграции и повторный запуск обновления.

Интерактивная проверка фронтенда через настоящие Go-обработчики с изолированными тестовыми заменами БД/S3:

```sh
FILEDROP_BROWSER_QA=1 go test ./internal/handler -run '^TestBrowserPreview$' -v -timeout 11m
```

Открывается `http://127.0.0.1:8080`, тест завершается через 10 минут или по Ctrl+C. Эти данные временные; production-бинарник не содержит демонстрационного режима и всегда использует PostgreSQL и S3.

Также добавлены `Makefile` (`make run`, `make test`, `make build`) и `Dockerfile`. Контейнер запускается с заполненным окружением, например `docker run --env-file .env -p 8080:8080 <image>`; для БД на хосте укажите доступный из контейнера адрес.

## Развёртывание

Фронтенд и API обслуживаются одним процессом и одним origin. При использовании reverse proxy задайте лимит тела **не меньше 2 ГиБ**, тайм-аут загрузки не меньше 30 минут и скачивания не меньше 35 минут. Например, для nginx:

```nginx
location / {
    proxy_pass http://127.0.0.1:8080;
    client_max_body_size 2g;
    client_body_timeout 1800s;
    proxy_send_timeout 1800s;
    proxy_read_timeout 2100s;
    proxy_request_buffering off;
    proxy_buffering off;
}
```

Приложение ограничивает начало загрузок 60 запросами в час на прямой IP. За reverse proxy этот адрес общий: настройте ограничение на доверенном прокси или измените политику в `internal/handler/router.go` под нужную нагрузку. Пользовательские `X-Forwarded-For` намеренно не используются. Сроки фоновой очистки требуют работающего процесса; после простоя он удаляет просроченные объекты при следующем запуске.
